Resource lifecycle ​

Resident explicit operators own CUDA workspaces and optional phase caches; CUDA low-rank operators can own a persistent channel-, readout-, or rank-distributed execution backend. Release these resources explicitly when the operator is no longer required outside recon_HOOp.

close ​

julia
close(op)

For resident HighOrderKernelOp, close synchronizes and releases its workspaces, phase caches, and multi-GPU workers. Derived normals share those resources and must no longer be used. Call it explicitly after recon_HOOp.

For HighOrderLowRankOp, this releases the distributed execution backend and the source operator's streaming/regeneration queue when present. Stored factors and other operator arrays remain owned until their references are dropped. To release only the distributed normal backend, use:

julia
release_highorder_normal_backend!(op)

recon_HOOp releases only the LowRank distributed normal backend by default, unless release_backend=false is requested. Call close(op) after the final use to also close a per-readout source queue. The wrapper does not close resident explicit operators.

Backend ownership and reuse ​

Rank mode initializes its backend on the first forward, adjoint, or normal request. Channel/readout modes initialize on the first normal request. The parent operator owns these resources; closing a derived low-rank normal view alone does not stop the parent's workers.

Backend release retains the parent's factor arrays. In rank mode the complete factor masters remain in host RAM while referenced. A later use of the parent can recreate its backend and required streaming/regeneration queue lazily; obtain a fresh normal view after release.

An owned distributed normal backend (:channel, :readout, or :rank) caches its weights. The :single path has no such cache. Before requesting different normal weights, release it and construct a new normal view. A direct normalOperator(op, D) call expects the already squared, real nonnegative diagonal of WHW; recon_HOOp accepts raw sample weights and applies them to data and encoding. See Weighting and cleanup.

Replace an operator ​

@rebuild_HOOp closes the previous value, clears its binding and runs garbage collection before evaluating the new constructor. Other references to that operator can still keep arrays alive. If the constructor fails, the old operator has already been released; the macro is not a rollback mechanism.

julia
@rebuild_HOOp variable constructor_expression

Safely replace a large high-order operator stored in variable.

If variable is already defined, its current value is closed when it supports Base.close, and the caller's binding is then set to nothing. A full Julia GC runs only after all temporary references to the old value have left scope. Finally, constructor_expression is evaluated and assigned to variable.

The constructor expression is evaluated after the old binding is cleared. Other references may still keep the old operator or its arrays alive. If the new construction fails, the previous binding is not restored.

Example ​

julia
@rebuild_HOOp HOOp HighOrderLowRankOp(
    grid,
    kspha,
    times;
    arrayType=CuArray,
    gpus=[1, 2, 3],
)

The first argument must be a plain variable name. In a local scope, its type must permit assignment of nothing.

Source: src/EncodingOperator/HighOrderLowRankOp.jl

Release only the distributed backend ​

julia
release_highorder_normal_backend!(op::HighOrderLowRankOp)

Release a low-rank parent's owned distributed backend and clear its cached normal weights. This applies to :channel, :readout, and :rank; the :single path has no such owned distributed backend. Return nothing. Repeated calls after release are harmless.

Complete factor arrays remain owned by op; this function also retains the parent's per-readout streaming/regeneration queue. Use close(op) to close that queue as well. A later use of the parent can recreate resources lazily. Derived normal views share the backend: stop using old views before release and obtain a fresh view afterwards. Release before changing distributed normal weights. Workspaces are not reentrant; do not release during an active product.

This is explicit lifecycle management, not an assurance that every allocation failure during construction is recoverable. CUDA memory pools may retain freed capacity for reuse.

Source: src/EncodingOperator/LowRankApproximation/multi_gpu_normal_operator.jl

CUDA.jl may retain released capacity in reusable memory pools. A high reserved memory value alone does not prove that an operator still owns live arrays. Construction-time allocation failures are a separate cleanup boundary: the current code does not establish complete recovery at every allocation site. See multi-GPU lifecycle.
